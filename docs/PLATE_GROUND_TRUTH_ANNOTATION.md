# Plate Ground Truth Annotation

This document describes the local Phase A annotation package for license-plate spatial review. The
package prepares source-backed review frames and draft files only. It is not yet Ground Truth.

## Certified Targets

- `day_plate`: `plate_day_01`, `artifacts/eval_day_plate.mp4`, parent frames `240-479`,
  dense frames `0-239`, source interval `bodycam_sample.mp4` `00:01:41.000-00:01:49.000`.
- `night_selective`: `plate_night_01`, `artifacts/eval_night_selective.mp4`, parent frames
  `420-779`, dense frames `0-359`, source interval `night_candidate.mp4`
  `00:04:56.000-00:05:08.000`.
- `artifacts/eval_day_plate_close.mp4` is excluded from this package.

## Annotation Policy

Annotate the smallest defensible rectangle around the physical plate panel. Do not draw the whole
vehicle, bumper, broad search ROI, text overlay, or reflection as the target box. Characters do not
need to be readable. For glare or overlay cases, annotate the defensible physical panel extent and
record a note when uncertainty remains.

The broad ROI is search-only metadata. It guides navigation and draft filtering, but it is never a
Ground Truth box.

## Draft Policy

Proposals may seed the package only when source hash, frame range, target identity, and clip mapping
align with the Phase A target. Proposals are hidden by default, do not count as reviewed, and are
stored separately from human boxes. Showing a proposal records `draft_shown=true`.

Assisted proposals are frame-specific. The builder first proves a candidate track belongs to the
certified target by comparing source-aligned track boxes against existing human-reviewed anchors.
For the night package this uses the 28 reviewed `plate_night_01` frames at parent frames `420-447`.
The broad QA ROI may help navigation, but it is never proposal geometry.

The assisted proposal priority is:

- `automatic_tracker_draft`: an exact-frame accepted target track box.
- `direct_detector_draft`: an exact-frame detector observation on a proven target track.
- `bounded_interpolation_draft`: a short internal gap bounded by trusted left and right detector
  anchors.
- `human_seeded_motion_draft`: reserved for future real motion-estimated propagation only.
- `privacy_envelope_draft`: reserved for explicitly labeled non-tight privacy-region fallback.

If the evidence is absent, unmatched, structurally implausible, or would require extrapolation, the
frame gets `proposal_available=false`. No-proposal frames are expected and safer than filling gaps
with uncertain geometry. Static long-range copying from the nearest human box is forbidden; the
legacy `human_seeded_propagation_draft` label must not be generated by the assisted builder.

## Assisted Annotation Package

The assisted workflow builds a new package from the reviewed v1 package without editing the v1
directory. Reviewed v1 records are migrated as human-reviewed boxes with their semantic annotation
fields preserved. Previously unresolved frames receive proposal records only when a proven
source-aligned target track supplies an exact-frame or bounded-gap candidate.

The assisted UI uses full source-frame assets rather than the static QA crop. The crop remains
search-only metadata and can be displayed as a QA ROI overlay, but saved boxes are always stored in
original full-frame coordinates. The assisted controls support one-click proposal acceptance,
proposal adjustment, Fit Frame, Fit Draft/Fit Box, zoom and pan, and keyboard shortcuts shown in the
toolbar.

Assisted provenance is recorded per frame:

- `proposal_available`, `proposal_bbox`, `proposal_source`, and `proposal_shown` describe the shown
  candidate.
- `proposal_quality=needs_human_adjustment` means the proposal localizes the target but is visibly
  broad, interpolated, or otherwise expected to need reviewer adjustment.
- `accepted_without_geometry_change=true` means the reviewer accepted the proposal exactly.
- `human_adjusted_geometry=true` means the reviewer saved a human box that differs from the proposal.
- `migration_audit.json` and `proposal_generation_audit.json` summarize source hashes, migrated
  reviewed records, proposal counts, and frames still without proposals.

## Secondary Plate Handling

Secondary records support `additional_localizable_plate`, `ignore_small`, and
`ambiguous_review_required`. Additional localizable plates require a box and receive deterministic
provisional IDs. Ignore-small records require a reason and remain non-negative examples. Ambiguous
records block final export until resolved.

## Temporal Ground Truth Conflicts

The frozen temporal Ground Truth remains authoritative: the mandatory day and night plate targets are
visible/localizable throughout the certified Phase A intervals. If a reviewer disagrees on a frame,
they must save the frame as `temporal_gt_conflict` with a non-empty note. Whitespace-only notes are
invalid. A conflict does not count as `reviewed_box`, does not complete the mandatory annotation, and
blocks final export until explicitly resolved.

A temporal conflict is resolved only when the reviewer saves a valid tight human box and the status
becomes `reviewed_box`. Showing a draft never resolves a conflict or creates a human box. Conflict
creation, notes, resolution, and the final human box remain in the append-only change log.

## Progress And Export Gates

Progress is counted by benchmark and total mandatory frames. The initial real package should show
`0 / 240` day reviewed boxes, `0 / 360` night reviewed boxes, and `0 / 600` total reviewed boxes.
Draft presence never changes those counts.

Final review export is locked until all 600 mandatory frames have valid human boxes and no unresolved
temporal or ambiguous records remain. Completed export revalidates the full package identity before
writing: package schema, certified target IDs, benchmark IDs, object type, action, parent/dense frame
mapping, expected counts, manifest identity hash, and actual evaluation video SHA-256 values must all
match the certified Phase A configuration.

## Machine-Readable Plate Ground Truth v1.0

`data/ground_truth/plate_ground_truth_v1.0.json` publishes the completed annotation review as
machine-readable license-plate spatial Ground Truth for the certified Phase A plate windows. Its
schema is `data/ground_truth/plate_ground_truth_schema_v1.0.json`.

The published dataset contains 600 final human-reviewed plate-panel boxes:

- `day_plate`: 240 records, parent frames `240-479`, dense frames `0-239`,
  target `plate_day_01`, evaluation video `artifacts/eval_day_plate.mp4`.
- `night_selective`: 360 records, parent frames `420-779`, dense frames `0-359`,
  target `plate_night_01`, evaluation video `artifacts/eval_night_selective.mp4`.

The dataset preserves explicit lineage to the completed review export, the frozen annotation
package, the two evaluation videos, and GroundTruth v1.1 temporal policy. The provenance truthfully
describes the boxes as proposal-assisted human-reviewed annotations and separates migrated manual
review, proposal accepted unchanged, proposal human-adjusted, and manual/no-proposal records.

`artifacts/eval_day_plate_close.mp4` remains excluded from certified plate Ground Truth. The
publication adds spatial Ground Truth only; it does not calculate detector recall, automatic
privacy coverage, or reviewed-final metrics. `evaluate-plates` remains capability-only until a
separate evaluator phase implements and audits plate scoring.

## Local Save Contract

The annotation server is a local loopback, single-reviewer workspace. One active human reviewer is
expected. Multiple browser tabs are possible, but each save includes a `state_revision`; stale tabs
whose expected revision no longer matches the current revision are rejected instead of silently
overwriting newer work. The tool does not provide multi-user merge semantics.

## Commands

```bash
redactor build-plate-annotation-package
redactor build-assisted-plate-annotation-package
redactor validate-plate-annotation-package artifacts/plate_ground_truth_annotation_v1/<run_id>
redactor summarize-plate-annotation-package artifacts/plate_ground_truth_annotation_v1/<run_id>
redactor serve-plate-annotation-package artifacts/plate_ground_truth_annotation_v1/<run_id>
```

For the assisted package:

```bash
redactor build-assisted-plate-annotation-package \
  --source-package artifacts/plate_ground_truth_annotation_v1/run_20260811T001554Z
redactor validate-plate-annotation-package artifacts/plate_ground_truth_annotation_v2_assisted/<run_id>
redactor serve-plate-annotation-package artifacts/plate_ground_truth_annotation_v2_assisted/<run_id>
```

To reproduce the completed review export and validate the published plate Ground Truth:

```bash
redactor export-plate-annotation-review \
  artifacts/plate_ground_truth_annotation_v2_assisted/run_20260811T185326Z \
  --final \
  --output artifacts/plate_ground_truth_publication_v1/run_20260811T200000Z/plate_annotation_review.export.json \
  --exported-at-utc 2026-08-11T20:00:00Z
redactor build-plate-ground-truth \
  --annotation-export artifacts/plate_ground_truth_publication_v1/run_20260811T200000Z/plate_annotation_review.export.json \
  --output data/ground_truth/plate_ground_truth_v1.0.json \
  --schema data/ground_truth/plate_ground_truth_schema_v1.0.json \
  --overwrite
redactor validate-plate-ground-truth \
  --ground-truth data/ground_truth/plate_ground_truth_v1.0.json \
  --schema data/ground_truth/plate_ground_truth_schema_v1.0.json
```
